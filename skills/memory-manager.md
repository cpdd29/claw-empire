# memory-manager

## 用途

本 skill 供秘书（tier=1）在每次对话结束时调用，将本次对话中的关键信息写入记忆文件。

## 触发时机

- 对话结束前，秘书判断本次对话有以下任一情况时触发：
  1. 用户透露了个人信息、偏好或习惯
  2. 用户对某个决策或结果表达了明确的满意/不满意
  3. 出现了需要跨会话记住的关键事项
  4. 用户明确要求「记住」某件事

## 调用方式

调用后端接口将记忆写入对应秘书的记忆文件：

```
POST /api/memories/{agent_id}/append
Content-Type: application/json

{
  "content": "<记忆内容，简洁描述>",
  "section": "<目标区块：## 用户信息 | ## 对话摘要 | ## 关键偏好>"
}
```

## 区块选择规则

| 内容类型 | 写入区块 |
|---|---|
| 用户姓名、职业、所在地等基本信息 | `## 用户信息` |
| 本次对话的核心结论、决策、任务结果 | `## 对话摘要` |
| 用户的风格偏好、习惯、反复强调的要求 | `## 关键偏好` |

## 记忆内容格式

- 每条记忆以 `- YYYY-MM-DD: ` 开头
- 内容简洁，不超过 100 字
- 使用第三人称描述用户（「用户」或用户姓名）
- 不记录无关闲聊，只记录有信息量的内容

## 示例

**对话内容：**
> 用户说：「我比较喜欢简洁的代码风格，不要加太多注释」

**调用示例：**
```json
{
  "content": "用户偏好简洁代码风格，不喜欢冗余注释",
  "section": "## 关键偏好"
}
```

---

**对话内容：**
> 用户完成了一个 React 组件重构任务，表示满意

**调用示例：**
```json
{
  "content": "完成 React 组件重构，用户满意，使用了 hooks 模式",
  "section": "## 对话摘要"
}
```

## 注意事项

- 不要在每次消息后都写入，只在对话结束或出现值得记录的关键信息时写入
- 避免重复记录相同内容（系统会自动去重，但尽量从源头控制）
- 隐私敏感信息（密码、密钥等）**不得**写入记忆文件
